# sketch-ui — how the style and color scheme works

Reference for the hand-drawn "wireframe / sketch" visual layer of Bllueprint
Studio. Read this before changing anything style related. The long-term plan
is in [`../../plano-sketch-ui.md`](../../plano-sketch-ui.md); this README
describes what **exists today** and how to extend it.

## 1. Folder map

```
src/sketch-ui/
├─ README.md                 ← this file
├─ components/               ← Spartan helms generated by the CLI (DO NOT edit, see §8)
│  ├─ sidebar/ button/ input/ separator/ sheet/ skeleton/ tooltip/ utils/
├─ core/                     ← alias @sketch-ui/core
│  ├─ theme.service.ts       ← theme and accent registries, applies attributes on <html>
│  └─ sketch-config.service.ts ← stroke width, fonts
├─ elements/                 ← alias @sketch-ui/elements: in-house sketch behaviour/elements
│  ├─ sketch-menu.directive.ts   ← `details[skMenu]`: close on outside click / Escape / item
│  └─ sketch-slider.component.ts ← `<sk-slider>`: wrapped range input (see §6 note)
└─ styles/
   ├─ index.css              ← SINGLE entry (registered in angular.json "styles")
   ├─ tokens.css             ← SHAPE tokens + derived tokens (ink, accent, hatches)
   ├─ themes/
   │  ├─ _contract.md        ← list of variables EVERY theme must define
   │  ├─ paper.css           ← light theme (dotted paper)
   │  ├─ blueprint.css       ← dark theme (blue, grid)
   │  └─ navy.css            ← dark theme (darker blue, dotted paper, no grid)
   ├─ base.css               ← SCOPED reset (replaces Tailwind preflight)
   ├─ sketch.css             ← @utility sketch, sketch-sm, sketch-line, … (Tailwind v4)
   ├─ components.css         ← hardcoded .sk-* components (playground, home)
   ├─ tabstrip.css           ← .sk-tabstrip* (workspace tabs and the editor's file tabs)
   └─ spartan-sketch.css     ← hand-drawn look on top of the helms (by data-slot), unlayered
```

Other places that take part in the scheme:

- `public/theme-init.js` — loaded by `src/index.html`, applies the stored theme/accent **before** bootstrap (no flash). External file, not inline, because of the CSP (`script-src 'self'`).
- `src/app/core/monaco/bllueprint-language.ts` — Monaco themes (`bllueprint-paper`, `bllueprint-blueprint`, `bllueprint-navy`).
- `public/fonts/comic-mono/` — editor font (optional), MIT license.
- `components.json` — Spartan CLI config (`componentsPath`, alias `@sketch-ui`, style `nova`).
- App icon: source glyph in `../../../Assets/AppIco*.svg` (curly brackets + abstract "B").
  The sidebar inlines it with `stroke="currentColor"` so it follows the theme ink.
  `public/favicon.ico` and the Electron icons are generated by
  `../bllueprint-desktop/scripts/build-icons.js` (`npm run build:icons` there) from
  `../bllueprint-desktop/assets/icon.svg`, which composes the glyph on the blueprint paper color.

## 2. How the CSS is loaded

`index.css` imports, in this order: Tailwind (`theme.css` + `utilities.css`,
**without `preflight.css`**), the `@spartan-ng/brain` preset, `tokens.css`, the
themes, the scoped reset, the utilities, the components and finally
`spartan-sketch.css`.

Why no preflight: the legacy editor chrome and Monaco use their own SCSS and
must not receive a global reset. `base.css` resets **only** inside
`hlm-sidebar`, `[data-slot=sidebar-trigger]`, `.cdk-overlay-container` and
`.sketch-root`. Any new sketch-looking surface needs the `sketch-root` class on
its root element to get the reset, the handwritten font and the paper
background.

Layers (`@layer theme, base, components, utilities`):

| File                             | Layer                        | Reason                                        |
| -------------------------------- | ---------------------------- | --------------------------------------------- |
| `base.css`                       | `base`                       | loses to any app rule                         |
| `components.css`, `tabstrip.css` | `components`                 | Tailwind utilities can override               |
| `sketch.css`                     | `utilities` (via `@utility`) | usable as classes in the helms                |
| `spartan-sketch.css`             | **unlayered**                | must beat the utility classes the helms apply |
| Angular component SCSS           | unlayered                    | as usual                                      |

The stylesheet is plain CSS (not SCSS) because Sass does not understand the
Tailwind v4 `@import`s. PostCSS runs through `.postcssrc.json`.

## 3. Tokens: shape vs color

**Golden rule:** no component uses a literal color (`#hex`, `oklch(...)`,
`bg-white`, `text-zinc-900`). Only the theme's semantic variables and the
`--sketch-*` tokens. Literal colors exist only in `styles/themes/*.css` and in
the hex mirrors for Monaco (see §7).

### 3.1 Shape tokens (`tokens.css`, `:root` block)

Identical in every theme.

| Token                                                         | Use                                                                             |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `--sketch-width`, `--sketch-width-inner`                      | outer / inner stroke width (the playground slider changes it)                   |
| `--sketch-radius`, `-sm`, `-round`, `-pill`                   | irregular radii that produce the wobbly stroke                                  |
| `--sketch-font`, `--sketch-font-active`                       | handwritten stack; `-active` becomes `--font-sans` under `html.sketch-font-off` |
| `--sketch-font-mono`                                          | Comic Mono + mono fallback                                                      |
| `--sketch-mask-line-h`, `-line-v`, `-check`, `-chevron`, `-x` | `data:` SVGs used as **masks** (the color comes from `background-color`)        |
| `--sketch-hatch`                                              | ink hatch for surfaces without text (default badge, skeleton)                   |
| `--sketch-roughness`, `--sketch-bowing`                       | reserved for the future Rough.js directive (L3); nothing reads them today       |

> An SVG in a `data:` URI cannot see CSS variables or `currentColor`. That is
> why every hand-drawn line is `background-color: var(--color)` + `mask: var(--sketch-mask-…)`.

### 3.2 Derived tokens (`tokens.css`, `:root, [data-theme]` block)

They reference the theme colors. They are declared **also on `[data-theme]`**,
not only on `:root`: a `var()` inside a custom property resolves on the element
where the property is **declared**. If they lived only on `:root`, a nested
panel with another theme (playground "side by side") would inherit the ink of
the `<html>` theme.

| Token                              | Value                              | Use                                             |
| ---------------------------------- | ---------------------------------- | ----------------------------------------------- |
| `--sketch-stroke`                  | `--foreground`                     | borders and text                                |
| `--sketch-stroke-muted` / `-faint` | foreground 38% / 16%               | inner lines, hover borders, shadows             |
| `--sketch-fill`                    | foreground 9%                      | ink hatch                                       |
| `--sketch-accent-soft`             | accent-fill 22% (30% on blueprint) | background of **active/selected** states        |
| `--sketch-accent-contrast`         | `--background`                     | text on a solid accent block                    |
| `--sketch-hatch-accent`            | accent stripes 55%                 | fills **without text** (progress, switch track) |
| `--sketch-hatch-accent-light`      | thin accent stripes 30%            | **hover** of any interactive item               |
| `--sketch-primary-hover`           | accent 85% + foreground            | hover of the primary button                     |

### 3.3 Color tokens (defined per theme)

The Spartan ones (`--background`, `--foreground`, `--primary`, `--muted`,
`--accent`, `--destructive`, `--border`, `--ring`, `--sidebar-*`, `--chart-*`…)
plus the sketch ones (`--sketch-accent`, `--sketch-accent-fill`,
`--sketch-paper-pattern`, `--sketch-paper-pattern-size`). The complete,
mandatory list is in [`styles/themes/_contract.md`](styles/themes/_contract.md).

Mind the name: `--accent` (Spartan) is a neutral hover/highlight **surface**.
The product's highlight color is `--sketch-accent`.

## 4. Themes

### 4.1 Attributes on `<html>`

| Attribute / class                                 | Set by                         | Purpose                                         |
| ------------------------------------------------- | ------------------------------ | ----------------------------------------------- |
| `data-theme="paper\|blueprint\|navy"`             | `ThemeService` + theme-init.js | selector of the theme files                     |
| `data-scheme="light\|dark"`                       | same                           | scheme, independent of the theme                |
| `.dark`                                           | same                           | the Spartan preset defines `dark:` as `.dark *` |
| `style="color-scheme: …"`                         | same                           | native controls (select, date, scrollbars)      |
| `data-accent="orange"`                            | same                           | accent selector (only one today)                |
| `.sketch-font-off`                                | `SketchConfigService`          | disables the handwritten font                   |
| `--sketch-width`, `--sketch-width-inner` (inline) | `SketchConfigService`          | playground stroke slider                        |

### 4.2 `ThemeService` (`core/theme.service.ts`)

- `SKETCH_THEMES`: registry `{ id, label, scheme, editorTheme }`. `editorTheme` is the name of the matching Monaco theme.
- `SKETCH_ACCENTS`: registry `{ id, label, editor: { <themeId>: { ink, fill } } }` with the hex mirrors Monaco needs.
- Persistence in `localStorage`: `sketch-ui.theme`, `sketch-ui.accent`. First visit honours `prefers-color-scheme`.
- `public/theme-init.js` repeats the minimal logic (ids and schemes) to apply before Angular. **Keep it in sync** with the registries.

### 4.3 Nested theme (side by side)

Any element can carry `data-theme`, `data-scheme` and `.dark` to render a
subtree in another theme. That is how the playground shows every theme at
once. It works because themes are attribute selectors and the derived tokens
are redeclared on `[data-theme]` (§3.2).

## 5. Accent usage rules (decided 2026-10-15)

| State                                                                                      | How to paint                                 | Token                                                                                                        |
| ------------------------------------------------------------------------------------------ | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Active / selected (tab, sidebar item, toggle, current page, calendar day, selected option) | flat soft background, ink border, ink text   | `background-color: var(--sketch-accent-soft)`                                                                |
| Hover of an interactive item                                                               | light hatch on top of the current background | `background-image: var(--sketch-hatch-accent-light)`                                                         |
| Primary button                                                                             | solid block with contrast text               | `background: var(--sketch-accent); color: var(--sketch-accent-contrast); border-color: var(--sketch-accent)` |
| Fill without text (progress, switch on)                                                    | full hatch                                   | `background-image: var(--sketch-hatch-accent)`                                                               |
| Marks (check, radio dot, switch knob, active item icon, link)                              | accent ink                                   | `var(--sketch-accent)`                                                                                       |
| Focus                                                                                      | dashed outline                               | `outline: var(--sketch-width) dashed var(--ring)` (`--ring` points to the accent)                            |

Never use the accent as a warning. Error/danger is `--destructive` (carmine,
deliberately far from the orange). Never put text on top of `--sketch-hatch-accent`.

## 6. Stroke layers

| Layer       | What                                 | Where                           | How to enable |
| ----------- | ------------------------------------ | ------------------------------- | ------------- |
| L1 CSS      | `border` + irregular `border-radius` | everything (default)            | always on     |
| L3 Rough.js | `[sketchBorder]` directive           | not implemented yet (plan §3.4) | —             |

The SVG displacement filter (L2) was tried and removed on 2026-10-16: it
distorted container borders without adding to the look. Lines that need a
hand-drawn wobble use the `--sketch-mask-*` masks instead.

> Masks and native `<input type="range">`: in Chromium the thumb is a child of
> the track, so a mask on the track clips the thumb. The slider's line is drawn
> by the host of `<sk-slider>` (`elements/sketch-slider.component.ts`, class
> `.sk-slider-wrap`), never by the input itself. Always use `<sk-slider>`.

## 7. Fonts and editor

- Chrome (sidebar, tabs, playground): `--sketch-font-active`. Local fallbacks
  (Segoe Print, Bradley Hand) keep the look offline in Electron; the Google
  fonts only come in if self-hosted under `public/fonts`.
- Code: `SketchConfigService.editorFont` (`mono` | `sketch`), persisted as
  `sketch-ui.editor-font`. `sketch` = Comic Mono (no ligatures, a conscious
  decision). `EditorHost` calls `monaco.editor.remeasureFonts()` after the font
  loads, otherwise the cursor drifts.
- The transparent background has a side effect: every Monaco widget that
  floats over the code needs a solid background in the theme
  (`editorStickyScroll.background`, `editorStickyScrollGutter.background`,
  `editorWidget.background`, `editorSuggestWidget.background`,
  `editorHoverWidget.background`…). If a new widget shows up "see-through",
  one of those keys is missing.
- Monaco does not read CSS. `registerSketchEditorThemes({ paper, blueprint })`
  in `bllueprint-language.ts` defines the themes with a transparent background
  (the paper shows through) and receives the accent hex values. `EditorHost`
  re-registers when theme or accent change and calls `setTheme`. The original
  `bllueprint-dark` theme stays registered, untouched.

## 8. Components: two worlds

1. **Hardcoded `.sk-*`** (`components.css`, `tabstrip.css`): native HTML with
   classes. This is what the playground, the Home and the tab strips use
   today. It validates the look before the helms are migrated.
2. **Spartan helms** (`components/`): generated with `ng g @spartan-ng/cli:ui <name>`
   and kept **exactly as generated**, so they serve as the diff reference for
   future Spartan updates. The hand-drawn look goes on top in
   `spartan-sketch.css`, by `data-slot` / `data-sidebar`. Only the sidebar (and
   its dependencies) is in use today.

The definitive migration (plan §4) is: for each helm, replace `rounded-*` and
`border-*` with the `sketch*` utilities, apply the §5 rules and replace the
equivalent `.sk-*` in the playground with the real helm.

## 9. How to create a new theme

Example: theme `graphite` (dark, grey).

1. **Theme file** — create `styles/themes/graphite.css` by copying
   `blueprint.css`. Change the selector to `[data-theme='graphite']`, adjust
   `color-scheme` and fill **all** the variables in `_contract.md`. Keep
   `--ring: var(--sketch-accent)` and `--sidebar-ring: var(--sketch-accent)`.
   Define `--sketch-accent` and `--sketch-accent-fill` for the new background
   (one tone on dark backgrounds; two tones on light ones, the text tone darker).
   If the 22% tint looks dull, override `--sketch-accent-soft`. Define the
   paper pattern (`--sketch-paper-pattern`/`-size`, or `none`).
2. **Import** — add `@import './themes/graphite.css';` to `styles/index.css`,
   after the other themes.
3. **Register** — in `core/theme.service.ts`, add to `SKETCH_THEMES`:
   `{ id: 'graphite', label: 'Graphite (dark)', scheme: 'dark', editorTheme: 'bllueprint-graphite' }`.
   In every entry of `SKETCH_ACCENTS`, add `graphite: { ink: '#…', fill: '#…' }`
   with the hex equivalents of the theme's `--sketch-accent` /
   `--sketch-accent-fill` (convert the oklch; a Node script with the
   oklch→sRGB formula does it).
4. **Bootstrap script** — in `public/theme-init.js`, add `graphite: 'dark'` to the `schemes` object.
5. **Monaco** — in `bllueprint-language.ts`, extend the `SketchEditorAccents`
   interface (and `DEFAULT_SKETCH_EDITOR_ACCENTS`) with the new key and pass it
   from `EditorHost`. For a chalk-on-dark theme one line is enough:
   `defineDarkSketchTheme('bllueprint-graphite', accents.graphite, { paper, card, raised })`
   with the hex mirrors of `--background`, `--card` and `--secondary` (that is
   how `navy` was added). Otherwise add a `defineTheme(...)` with `base: 'vs'`
   or `'vs-dark'`, `LIGHT_RULES`/`BLUEPRINT_RULES` (or an own palette),
   background `#00000000` and the theme's hex colors for the floating widgets.
6. **Validate** — in the playground: select the theme, enable "All themes side
   by side", check text and focus contrast, open the native select and a
   `<dialog>`, and switch to the Editor tab (cursor, selection, line numbers).
   Test both font states. Run `npx ng build` (the global CSS budget is
   generous, but the per-component one is 16 kB: theme styles never go into
   component SCSS).

If the theme is only a new palette with no shape tweaks, steps 1 to 4 take
minutes; step 5 is the only one with code.

## 10. How to add an alternative accent

1. In **every** theme, add a block
   `[data-theme='<theme>'][data-accent='<id>'], [data-accent='<id>'] [data-theme='<theme>']`
   defining `--sketch-accent` and `--sketch-accent-fill` (the second form is
   what makes side-by-side work).
2. Add the entry to `SKETCH_ACCENTS` with the per-theme hex values.
3. Add the id to the `accents` array in `public/theme-init.js`.
4. To compare, a `<select>` bound to `ThemeService.setAccent()` in the
   playground is enough (the one that existed on 2026-10-15 was removed after
   orange was chosen).

## 11. Checklist before closing any style change

- No literal color outside `styles/themes/` and the Monaco hex mirrors.
- Works in both themes and side by side.
- Text never on top of a hatch; active state uses the soft tint; hover uses the light hatch.
- Focus visible (dashed outline in the accent).
- Native selects and dialogs follow the theme (`color-scheme` + painted `option`).
- No global preflight; new surfaces get `.sketch-root`.
- Helms in `components/` remain untouched.
- `npx ng build` passes; if `tsconfig.json`/`angular.json` changed, restart `ng serve`.
- Everything (code, comments, docs) is in English.
